# panaudia-lasa

The Panaudia LASA server: the `lasa` protocol shell composed with the
panaudia spatial renderer into one process serving one space. Two Go
modules, `engine/` (the renderer) and `server/` (the binary), and a
Docker recipe.

## Run from source

Needs Go 1.26 and libopus (`brew install opus pkg-config` on macOS,
`apt install libopus-dev pkg-config` on Debian). From `server/`:

```bash
PANAUDIA_ALLOW_UNTICKETED=true go run .
```

Configuration is environment variables only, listed with defaults and
meanings in [`server/.env.example`](server/.env.example). For
development, copy it to `server/.env` and it is loaded at startup; real
environment variables always win over the file. The server prints its
full effective configuration, with each value's source, when it
starts. There are no flags.

## Docker

One `Dockerfile` for every target, building from this checkout:

```bash
docker/build                      # linux/amd64, version from the server/v* git tag
PLATFORM=linux/arm64 docker/build # native on Apple silicon
docker run --rm -p 4443:4443/udp -e PANAUDIA_ALLOW_UNTICKETED=true \
  panaudia/panaudia-server:0.3.0-amd64
```

The version the binary prints and the image is tagged with comes from
git: tag a release `git tag server/vX.Y.Z` and both follow. A plain
`go build` from a tagged checkout reports the same version through the
Go build info; anything else reports `dev`.

The runtime image is `debian:trixie-slim` plus `libopus0` and the
binary, running as an unprivileged user; about 175 MB, nearly all of
it the Debian base. It listens on 4443/udp; map it to 443 with
`-p 443:4443/udp` if you want the conventional port. On amd64 the
GEMM hot path is static libxsmm, embedded in the binary (the build
verifies it); on arm64 it is the pure-Go gonum backend, identical in
output, slower.

The process stops cleanly on SIGTERM/SIGINT (`docker stop`, an
orchestrator's rolling restart): it stops accepting, closes every live
session with the LASA "space shutting down" code so clients can tell a
stop from a network failure, waits up to five seconds for their
departures, then exits 0. A configured certificate pair is re-read when
the files change, so a renewal on the host or a rotated mounted secret
takes effect without a restart.

Configure with `-e` variables, or mount a `.env` at
`/opt/panaudia/.env` (the working directory) or anywhere with
`-e PANAUDIA_ENV_FILE=/path`. A ticketed space wants `PANAUDIA_TICKET_KEY`
and real certificates via `PANAUDIA_CERT`/`PANAUDIA_KEY`, mounted in.

[`third-party-licences.md`](third-party-licences.md) lists every
dependency the binary and image distribute, with licence texts; it is
generated by `tools/gen-third-party-licences.py` and a test fails when
the build graph gains a module it does not cover. The image carries it
at `/licenses/`.

## CI and releases

`.github/workflows/ci.yml` runs on every push and pull request: gofmt,
vet and `go test -race` for both modules, the engine's gemm and parity
suites against static libxsmm (`-tags xsmm`, the production x86 path),
and a no-push build of the Dockerfile. `.github/workflows/image.yml`
publishes on a server release tag:

```bash
git tag server/v0.3.0 && git push origin server/v0.3.0
```

That produces one multi-architecture image,
`ghcr.io/panaudia/panaudia-server:0.3.0` (and `:latest`), amd64 with
libxsmm and arm64 on the gonum path, with the same version baked into
the binary. `docker/build` remains the local, single-architecture
equivalent.

## Health and stats

`PANAUDIA_HTTP_PORT` (off by default) opens a plain-HTTP TCP port for
the things that supervise a server:

- `GET /healthz` is liveness: 200 while the process is up.
- `GET /readyz` is readiness: 200 while accepting sessions, 503 from
  the moment shutdown begins, so a balancer drains before the sessions
  close.
- `GET /stats` is the diagnostics snapshot as JSON: version, space,
  uptime, the engine's render counters, and per-entity ingest
  diagnostics (jitter depth, loss, decode and encode errors).

It is a separate port so it can stay on the private network; the
snapshot names entities and clients. A Kubernetes deployment points
`livenessProbe` at `/healthz` and `readinessProbe` at `/readyz`;
Docker Compose can use `curl` from another container, as the image
ships no HTTP client of its own.

```bash
docker run --rm -p 4443:4443/udp -p 127.0.0.1:8080:8080 \
  -e PANAUDIA_ALLOW_UNTICKETED=true -e PANAUDIA_HTTP_PORT=8080 \
  panaudia/panaudia-server:0.3.0-amd64
curl -s localhost:8080/stats
```

QUIC wants large UDP socket buffers; quic-go logs a warning when it
cannot get them. On Linux hosts raise them once
(`sysctl -w net.core.rmem_max=7500000 net.core.wmem_max=7500000`), or
run the container with `--sysctl` if your runtime allows it.
